* Scope
:PROPERTIES:
:CUSTOM_ID: scope
:END:

How ~demo~ is shown to meet its requirements and its ICD before it is
released.  Verification asks "did we build it right": every requirement
with method T is covered by a numbered test case here, every ICD clause by
a monitor.  Validation ("did we build the right thing") is the system
test, outside this document.



- Items under test :: ~src/demo.vhd~, ~src/demo_pkg.vhd~
- Requirements :: [[file:demo_srs.org::#requirements][demo requirements]], version 1.0.0
- Interface :: [[file:demo_icd.org::#scope][demo ICD]]
- Results :: reported in the [[file:demo_test_report.org::#results][demo test report]]

* Strategy
:PROPERTIES:
:CUSTOM_ID: strategy
:END:

| Level       | What                                      | Tool              | Verdict                             |
|-------------+-------------------------------------------+-------------------+-------------------------------------|
| Unit        | ~tb_demo~: numbered test cases, monitors  | GHDL, ~make test~ | ~TEST PASSED~ in the log            |
| Integration | Block in the top level, BFMs on the buses | GHDL              | ~TEST PASSED~                       |
| Static      | CDC report, timing report, utilisation    | Vivado / Quartus  | no unconstrained crossing, WNS >= 0 |
| Hardware    | Driver smoke test on the board            | target board      | checklist in the test report        |

What simulation cannot show: metastability, timing, how the tool maps the
code.  Those are the static level, and they are not optional.

** Bad weather
:PROPERTIES:
:CUSTOM_ID: bad-weather
:END:

The stimulus behaves like software that ignores the ICD: double start,
writes while busy, a reboot in the middle of a transaction, enable before
the clock is stable.  The expected result is always the same: the block
stays safe, the bus is never locked, and the monitor for the clause fires.

* Contract monitors
:PROPERTIES:
:CUSTOM_ID: monitors
:END:

Independent processes in ~tb_demo~ that drive nothing and stop the
simulation on an ICD violation.  One per clause, named after it.  A monitor
that never fires in the bad-weather tests is a monitor that does not work.

| Monitor                      | ICD clause        | Fires in |
|------------------------------+-------------------+----------|
| ~p_tw_no_start_while_busy~   | [[file:demo_icd.org::#illegal-sequences][illegal sequences]] | TC-10    |
| ~p_tw_busy_follows_start~    | [[file:demo_icd.org::#latency][latency]]           | never    |
| ~p_tw_done_within_max~       | [[file:demo_icd.org::#latency][latency]]           | never    |
| ~p_tw_bus_response_within_2~ | [[file:demo_icd.org::#bus-access][bus access]]        | never    |
| ~p_tw_soft_rst_aborts~       | [[file:demo_icd.org::#illegal-sequences][illegal sequences]] | TC-11    |

* Mutation checks
:PROPERTIES:
:CUSTOM_ID: mutations
:END:

A test that has never failed has not shown it can.  Each test case is broken
once on purpose, the failure is seen, and the change undone.

* Coverage
:PROPERTIES:
:CUSTOM_ID: coverage
:END:

- Requirements: every T requirement has a TC in the table above; the
  
  [[file:demo_rtm.org::#matrix][traceability matrix]] is the check.
- Code: every FSM state entered and left; every ~case~ branch including
  ~others~.  Measured with ~ghdl --coverage~ or by inspection of the log.
- Functional: each ICD side effect exercised at least once.
