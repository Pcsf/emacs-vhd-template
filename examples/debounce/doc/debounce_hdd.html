2. Overview

Two flip-flops bring din into the clock domain. A counter measures for how long the synchronized level has differed from the output; when it reaches C_LIMIT the output takes the new level. 

        +---------+   +---------+      +-----------------------+
din --->| sync(0) |-->| sync(1) |--+-->| /= stable ? count     |
        +---------+   +---------+  |   |  = stable ? clear     |
                                   |   +-----------+-----------+
                                   |               | cnt = C_LIMIT
                                   |          +----v----+
                                   +--------->| stable  |---> dout
                                              +---------+
File Unit Purpose
src/debounce.vhd debounce The block, one clocked process
tb/tb_debounce.vhd tb_debounce Test cases and tripwire monitors

3. Clocks and resets

One clock. rst is synchronous and active high, and is the last statement of the process, so it wins over the count. It resets stable and cnt and leaves the synchronizer alone.

Clock Frequency Source Used by Constraint
clk G_CLK_HZ system clock the whole block create_clock at the top

4. Clock domain crossings

From To Signal(s) Structure Constraint Verified by
pin clk din sync, two flip-flops false path on din inspection; no CDC run

sync carries async_reg (Xilinx) and SYNCHRONIZER_IDENTIFICATION (Intel) and has no reset, so nothing sits between its two stages.

5. Block design

5.1. Structure

The block is one clocked process with three signals. It is not in the two-process style: with a synchronizer chain and one counter there is no next-state logic worth separating.

Signal Width Reset Purpose
sync 2 none Synchronizer; sync(1) is the level used
stable 1 0 The debounced level, drives dout
cnt range 0 to C_LIMIT 0 Clocks for which sync(1) differed

5.2. Control

There is no state machine. Each clock takes one of three branches:

Condition Action
sync(1) = stable cnt := 0
sync(1) /= stable and cnt = C_LIMIT stable := sync(1), cnt := 0
sync(1) /= stable otherwise cnt := cnt + 1

The count goes from 0 to C_LIMIT before the level is taken, which is why a change needs C_LIMIT + 1 samples and not C_LIMIT.

5.3. Datapath

None beyond the counter: ceil(log2(C_LIMIT + 1)) bits, 20 with the defaults.

5.4. Register interface

None.

6. Design decisions

Decision Consequence at the port
The synchronizer is inside the block and not reset A closed contact reads open after reset (ICD)
The count is cleared by one sample of the old level An input that never rests is never passed on
C_LIMIT is computed as G_CLK_HZ / 1000 * G_DEBOUNCE_MS No overflow of natural; clock cut to whole kHz

8. Observability

cnt and stable are the two signals to look at; in a waveform the count ramps while the input differs and falls to 0 at every bounce.
